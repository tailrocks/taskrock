# Facts proven by test

This page lists the facts about GitHub, the `gh` command, agent CLIs and the CI of this repository that taskrock depends on. Each row says how its fact was seen: a live test on GitHub, a measurement, a read of a page, or a trap found during the build. A fact can change when GitHub or a tool changes, so check it again before a change that depends on it. The choices that stand on these facts are in [design](design.md).

## How to prove a fact again

The live tests are the files in `crates/taskrock/tests/` whose names start with `sandbox_`. `sandbox_gh.rs` reads the repository `tailrocks/taskrock-sandbox`. `sandbox_claim.rs` and `sandbox_apply.rs` write to that repository and to a test project. `sandbox_setup.rs` runs `taskrock setup` twice on the sandbox project 10 with `fixtures/config-sandbox.toml`. `sandbox_items.rs` reads the items of the project `https://github.com/orgs/tailrocks/projects/3`, so it needs read access to that project. Four live tests sit in `cli.rs` and read the merged pull request `https://github.com/tailrocks/taskrock/pull/153`: `pr_status_json_prints_the_verdict_as_json`, `pr_threads_json_prints_the_report_as_json`, `pr_threads_resolve_json_refuses_and_writes_nothing` and `pr_merge_json_prints_the_report_as_json`. They write nothing (`pr merge` finds the pull request merged), and the first, second and fourth fail when `--json` is dropped before the renderer. The third needs no JSON to refuse, so it stays green then. Each test has `#[ignore = "talks to GitHub"]`, so the normal test run skips them. Run one file from the tool repository with `cargo test -p taskrock --test sandbox_claim -- --ignored`, or the `cli.rs` live tests with `cargo nextest run --workspace --all-features --locked --run-ignored all -E 'test(json)'`, while `gh` is logged in to an account that can write to the sandbox.
